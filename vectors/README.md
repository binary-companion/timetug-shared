# Golden vectors

Reference answers produced by the Swift code of this library at the baseline tag (`1.8.1`) and replayed by the Rust tests of the `v2` port (Rust conventions, section 9). Nothing here is written by hand: every file is generated by the `VectorExporter` executable (`Sources/VectorExporter/`), and a vector is never edited or regenerated to make Rust pass. If Rust and a vector disagree, the Rust code is wrong or the disagreement is reported.

## Regenerate

```bash
scripts/dev/export-vectors.sh          # swift build -c release --product VectorExporter -Xswiftc -enable-testing, then runs it
git diff --exit-code vectors/          # must be empty: the exporter is deterministic
```

The exporter needs `-Xswiftc -enable-testing` because it reaches internal entry points with `@testable import`. Run it on macOS. The CI job `vectors-current` (`macos-26`) does the same on every pull request and push and fails if a committed file differs.

The vectors depend on the runner's Foundation, Unicode data and time zone database. If a later runner image changes a zone's rules or Foundation's folding tables, `vectors-current` fails. The fix is to pin the affected cases to past dates (or drop the character), never to accept the new output silently.

## Format

Every file is one JSON document:

```json
{ "schema": 1, "area": "dedup/pair-decisions", "baseline": "1.8.1",
  "cases": [ { "name": "hand-exact-match-other-calendar", "input": { }, "expected": { } } ] }
```

- `area` is the path of the file under `vectors/` without `.json`. Case names are unique within a file; hand-written cases come first (`hand-...`), then generated ones (`generated-...`).
- Instants are integer Unix milliseconds, zones are IANA identifiers, durations are seconds. The two exceptions are named in `wire/dates.json` (a `Double` of seconds, because the wire code takes a `Date`) and in the ledger JSON of `takeover/ledger.json` (Swift's default `Date` coding, seconds since 2001-01-01, because that is the persisted format).
- Generated cases come from the fixed-seed `LCG` of `Sources/VectorExporter/LCG.swift` (`state = state &* 6364136223846793005 &+ 1442695040888963407`, returning `state >> 33`); each area's seed is a constant at the use site.
- Files are written by `JSONSerialization` with `.prettyPrinted` and `.sortedKeys`. A `Double` is written with 17 significant digits; read it with a correct parser.
- The shape of `input` and `expected` of every area is documented in a comment at the top of the area's exporter file (`Text.swift`, `Dedup.swift`, `Takeover.swift`, `Agenda.swift`, `Wire.swift`, `Inference.swift`). The event shape that several areas share (`EventSpec`) is documented in `EventSpec.swift`. The Rust replay tests follow those comments.
- No real calendar content is used. Titles, places, e-mail addresses and links come from small fixed pools in the exporter (placeholders such as `x.com` addresses).

## Not covered

- The ledger's size cap is covered by one case (`takeover/ledger.json`, `cap-2100-events-fired-then-pruned`); the retention window by `hand-prune-retention`. The cap on lessons and verdict entries (`LessonBook.maxLessons`, `VerdictCache.maxEntries`) is covered by the Swift tests only.
- `TextGeneratorAdjudicator`'s deadline and request cap (`maxRequests`) are not exported; only the one-word answer parsing is.
